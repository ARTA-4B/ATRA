# Code of conduct

ATRA is a small open-source project run by one maintainer. These are the
expectations for everyone who takes part in it: issues, pull requests,
discussions, and any other space the project uses.

## The standard

Be direct, be specific, be decent. Criticise code and claims freely; do not
attack people. A review that says "this rounds toward the trade and the spec
says away from it, see risk/money.ts" is welcome. A review that says the
author is careless is not.

Concretely, this is expected:

- Disagreements are about the work, argued with evidence, and end when the
  evidence is in.
- Newcomers get the same answer an old hand would, without condescension.
- Nobody is asked for a seed phrase, a private key, a password, an account
  or a payment in a project space, ever, for any reason. Anyone who asks is
  not acting for the project.
- Financial claims are held to the same standard as code: no numbers that
  did not happen.

And this is not tolerated:

- Harassment, threats, stalking or doxxing, in project spaces or elsewhere
  when it concerns a participant.
- Discrimination or demeaning remarks about who someone is.
- Sexualised language or attention.
- Trolling, sustained disruption, or deliberately wasting maintainers' time.
- Promoting a token, a pump, a "signal" or an investment in project spaces.
  The support token is disclosed in [docs/token-disclosure.md](docs/token-disclosure.md);
  that is the only place it belongs.
- Impersonating the project, the maintainer, or another contributor.

## Reporting

Report conduct problems privately to the maintainer through a
[GitHub private security advisory](https://github.com/ARTA-4B/ATRA/security/advisories/new)
with "conduct" in the title, or by contacting the maintainer directly through
the GitHub profile of the repository owner. Reports are read by the
maintainer only, kept confidential, and answered.

If the report concerns the maintainer, say so; there is nobody else to
escalate to inside this project, and the honest answer is that a
one-maintainer project cannot offer independent adjudication.

## Consequences

The maintainer decides, proportionately: a warning, a removed comment, a
locked thread, a temporary block, or a permanent ban from the project's
spaces. Decisions are explained to the person concerned.

## Scope and attribution

This applies to all project spaces and to public spaces when someone is
representing the project. It is written for this project and borrows the
shape of the Contributor Covenant without copying its text.
