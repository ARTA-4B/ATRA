# Security release checklist

Written for: whoever decides that V1 is ready, and whoever audits that
decision later. Every line below is one line of the release gate in the
project specification (section 11). For each, this document names the test
or the code that proves it and records what was actually run, on which
date, with what result. A line without proof says **NOT VERIFIED** and what
would prove it. Ticks are not aspirational; a tick that cannot be reproduced
is a bug in this document.

`scripts/release-gate.sh` runs every automatable line and prints the same
table. Run it before tagging anything.

**Verdict on 2026-09-20 (second pass): the tree passes the gate; the
history does not.** The tracked data directories are untracked and ignored,
the LP boot-order defect is fixed with a test in the production order, and
the broadcast-failure path is now covered. What remains is a decision, not
work: the encrypted probe vault committed in `9a44c3b` is still in the
public history. Either rewrite history before tagging V1 or accept it and
document the two probe wallets as burned. That decision is the owner's.

Last run: 2026-09-21, this checkout (runtime 705 tests in 27 files, gateway
112, frontend 16 Playwright), Windows 11, Node 24.17.0, pnpm 11.9.0. The
public site and the gateway are deployed, so the rows below that used to say
"claimed by its owner" are now checked against the running service.

## Known open defects at the gate

From the Phase 4 report, revised on 2026-09-21 after the audit round. None
of them lets a key out or lets a model sign, which is why they never
blocked, but they are listed so nobody discovers them in production. Most
are now struck through; what remains is what is genuinely still open:

1. ~~Boot order defeats the LP reconcile~~ — fixed on 2026-09-20, see the restart row.
2. ~~Both schedulers map intervals other than whole minutes to a 59-second
   cron step~~ — fixed on 2026-09-20. Both now arm a plain period, croner is
   gone as a dependency, and `test/scheduler.test.ts` measures the firing
   rate for 90 s, 7 min and 24 h rather than asserting a pattern.
3. ~~The LIVE LP executor has no simulation step before signing~~ — fixed on
   2026-09-21: it builds, simulates what it built, then signs, so a revert
   no longer costs gas and a cooldown.
4. LP outcomes raise no Telegram notification.
5. `mainnet.base.org` rate-limits the LP adapter's pool read; a keyed Base
   RPC is needed for auto-LP there.
6. The Telegram `/lp` summary prints `null USD` for an unpriced position
   instead of "unknown".

## How to re-run this checklist

```sh
sh scripts/release-gate.sh          # everything automatable, a few minutes
sh scripts/secret-scan.sh           # the scan alone
cd runtime && pnpm audit --prod && npx vitest run
cd gateway && pnpm audit --prod && npx vitest run
npm audit --omit=dev                # the frontend, at the repo root
cd model/atra-4b && python -m pytest tests -q
```

Update the "Last run" line and the results table with what you saw. If a
line went from PASS to anything else, the release waits.
